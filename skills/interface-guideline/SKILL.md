# Interface Guideline

Use this skill when planning, implementing, or reviewing the POS user interface.

## Interface Purpose

The interface should help a cashier complete one snack bar cash transaction using a mouse and keyboard on a desktop or laptop computer. It does not need touchscreen gestures or kiosk behavior.

## Required Interface Areas

Keep these areas clearly distinguishable, whether they are on one screen, in tabs, or in simple sections:

- Product list with item names, prices, and add buttons.
- Cart or order summary with item quantities, subtotals, total, and quantity controls.
- Payment entry with amount paid input, validation message, and confirm action.
- Receipt area with transaction details and new transaction action.

## Layout Guidance

Prefer a direct POS layout:

- Put products and cart summary where they can be scanned together.
- Keep payment controls near the total amount.
- Keep receipt output visually separate from active cart editing.
- Use readable font sizes and button sizes for desktop use.
- Label controls with cashier-friendly words such as Add, Remove, Pay, and New Transaction.
- Show totals with consistent currency formatting.

## Feedback Guidance

Provide clear feedback for both success and errors:

- Show a short message when an item is added or payment succeeds.
- Show invalid payment messages near the payment input.
- Show insufficient payment with the minimum required amount.
- Keep messages visible long enough for screenshots.
- Do not rely on color alone; use clear text.

## Evidence-Friendly Screens

The exam requires screenshots of product list, cart, payment, receipt, and GitHub history. Make app screens easy to capture:

- Product list should show product names and prices at once.
- Cart screenshot should show items, quantities, subtotals, and total.
- Payment screenshot should show successful payment and computed change.
- Receipt screenshot should show items, total, amount paid, change, and transaction reference.

## Review Checks

Before finalizing interface work, confirm that the UI supports the full transaction without hidden steps, unclear labels, overlapping text, or missing required information.
